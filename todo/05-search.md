# M5: 検索（距離計算・top-k・フィルタ）← ベクトル検索の本体

## このマイルストーンでやること

ついに**「似ているベクトルを探す」**機能を作ります。やることは3つ:

1. **距離・スコアの計算**（`metric.rs`）: Cosine / L2 / Dot の3通り
2. **上位 k 件を選ぶ**（`search.rs`）: 全件スコアを出して、良い順に k 件だけ取り出す
3. **配線**（`db.rs`）: `db.search(query, k, opts)` として使えるようにする

仕組みはとてもシンプルです。**「保存してある全ベクトルとクエリの“似ている度”を1個ずつ計算 → 良い順に並べて上から k 件返す」
**。これだけ。賢い索引（ANN）は使いません（全探索 / ブルートフォース）。

## なぜ似ている＝距離なのか（ベクトル検索の超基礎）

AI は「意味が近いもの」を「近い場所のベクトル」に変換します。だから「2つのベクトルがどれくらい近いか」を測れば、「意味がどれくらい似ているか」が分かります。その「近さの測り方」がメトリックです。

## 3つのメトリック（SPEC §6.1）

`a` をクエリ、`b` を保存済みベクトルとします。

### Dot（内積）— 一番素朴

```
dot(a, b) = a0*b0 + a1*b1 + ... + a(n-1)*b(n-1)
```

大きいほど「同じ方向に強く向いている」。これがそのままスコア。

### Cosine（コサイン類似度）— 向きだけ見る（長さを無視）

```
cos(a, b) = dot(a, b) / (‖a‖ * ‖b‖)     範囲は -1 .. +1
```

`‖a‖` はノルム（長さ）。割ることで「長さの違い」を打ち消し、**向きの近さだけ**を測る。1に近いほど似ている。

- 例: `[1,0]` と `[100,0]` は向きが同じなので cos≈1（長さが100倍違っても“似ている”）。

### L2（ユークリッド距離）— 普通の直線距離

```
l2(a, b) = √( (a0-b0)² + (a1-b1)² + ... )
```

小さいほど近い＝似ている。

## スコアとディスタンスの約束（ここ重要）

EmveDB は結果を**「良い順（best-first）」**で返します。そのために:

- **`score`** … メトリックに関係なく**「大きいほど似ている」に統一**した値。並び替えはいつもこれで降順。
- **`distance`** … 人間が見て分かりやすい「生の距離」（小さいほど近い）。

| metric | distance         | score（大きいほど良い）       | ランキング                   |
|--------|------------------|----------------------|-------------------------|
| Cosine | `1 - cos`        | `cos`（−1..1）         | score 降順                |
| L2     | ユークリッド距離         | `-distance`（距離にマイナス） | distance 昇順（= score 降順） |
| Dot    | （なし。score と同値扱い） | 内積                   | score 降順                |

つまり「内部では score で降順ソートするだけ」。distance は表示用に後から復元します。

## 出てくる言葉

| 言葉                   | 意味                                                   |
|----------------------|------------------------------------------------------|
| top-k                | 一番良い k 件。                                            |
| 有界ヒープ (bounded heap) | サイズを k に固定した優先度付きキュー。全件ソートより速く top-k が取れる。           |
| min-heap             | 一番小さい要素がすぐ取れるヒープ。top-k では「今の k 件の中で最弱」をここに置く。        |
| ゼロノルム                | 全要素0のベクトル。Cosine では割り算できず類似度を定義できない → score=−∞（最下位）。 |
| フィルタ                 | 「この id は検索対象に入れる？」を判定するコールバック。`false` なら除外。          |

## 手順（タスク）

### 1. `metric.rs`：計算の本体

- [ ] `dot(a: &[f32], b: &[f32]) -> f32` … 要素ごとの積の合計
- [ ] `l2_sq(a: &[f32], b: &[f32]) -> f32` … 差の二乗の合計（**平方根はまだ取らない**＝二乗距離）
- [ ] Cosine: `cos = dot(a,b) * inv_norm_a * inv_norm_b`
    - `inv_norm_b`（保存側）は index が前計算済み（M3）。`inv_norm_a`（クエリ側）は検索開始時に**1回だけ**計算する
- [ ] 各メトリックについて `(score, distance)` を返す関数を用意
- [ ] ゼロノルム処理: Cosine でクエリか保存ベクトルのノルムが0なら score=`f32::NEG_INFINITY`（最下位）

> なぜ二乗距離でランキング？ → L2 の順位は「距離」でも「距離の二乗」でも同じ（√は単調増加）。平方根は重いので、ランキングは二乗のまま行い、最後に勝ち残った
> k 件にだけ √ をかけて `distance` を作ると速い。

### 2. `search.rs`：オプションと top-k

- [ ] 結果型
  ```rust
  pub struct SearchResult { pub id: u64, pub score: f32, pub distance: f32 }
  ```
- [ ] オプション型
  ```rust
  pub struct SearchOptions {
      pub filter: Option<Box<dyn Fn(u64) -> bool + Send + Sync>>,
      pub min_score: Option<f32>,  // これ未満のスコアは捨てる足切り
  }
  ```
- [ ] **サイズ k の min-heap で top-k を保つ**（全件ソートより速い: `O(N log k)`）
    - 考え方の擬似コード:
      ```
      heap = 空の min-heap（容量 k、score の小さい順に取り出せる）
      for each (id, vector) in ライブ全件:
          if filter があって filter(id) == false: スキップ
          score = scoreを計算(query, vector)
          if min_score があって score < min_score: スキップ
          if heap.len() < k:
              heap に push
          else if score > heap の最小要素の score:
              heap の最小を pop して、新しいのを push
      最後に heap を score 降順にソートして Vec にして返す
      ```
    - 浮動小数の比較は `f32::total_cmp` を使うか、NaN を除外したラッパ型で順序を定義する（`f32` は素の `Ord` を持たないため）
- [ ] 最後にヒープを score 降順へソートして `Vec<SearchResult>` にする

### 3. `db.rs::search(query, k, opts)`

- [ ] RW でも RO でも呼べる（読み取りロック。M7 で本対応）
- [ ] クエリ長 ≠ dimension → `DimensionMismatch`
- [ ] Cosine ならクエリの `inv_norm` を前計算
- [ ] `index.iter_live()` を回し、`filter` が false の id を飛ばし、`min_score` で足切りしつつ top-k に入れる
- [ ] 境界の挙動を決める: `k == 0`（空を返す）、`k > live`（ライブ全件返す）
- [ ] top-k を返す

## 動作確認（受け入れ条件）

- [ ] 既知のデータで、各メトリックの順位が**素朴な参照実装**（テスト内で全件ソートする愚直なループ）と一致する。
- [ ] Cosine: 向きが同じで長さだけ違うベクトルが score≈1。ゼロノルムが最下位。
- [ ] L2: `distance` が本物のユークリッド距離になっていて、順位は二乗距離と一致する。
- [ ] `filter` で除外した id が結果に出ない。`min_score` 未満が落ちる。
- [ ] `k=0` で空、`k>live` でライブ全件、同点のときの順序が定義どおり安定。

## つまずきポイント / 実装メモ

- まずは**素直な二重ループ**で正しく動かす。SIMD / `wide` / `bytemuck` での高速化は M8 のベンチで遅さを確認してから（早すぎる最適化は禁物）。
- 数値の精度: f32 のままで良い。大次元で誤差が気になるなら、内積を f64 で足し込む手もある（その余地だけメモしておく）。
- 「参照実装と比較するテスト」が最強。愚直に全件 `(score, id)` を作って `sort` したものと、ヒープ版の結果を突き合わせれば、ヒープのバグがすぐ見つかる。
- ANN は v1 対象外。ただし将来差し替えやすいよう、「候補を出す → スコアを付ける」を分離できる形にしておくと良い（任意）。

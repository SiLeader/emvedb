# M2: ストレージ層（実ファイルの読み書き・壊れ回復・ロック・:memory:）

## このマイルストーンでやること

M1 で作った「バイト列の文法」を、いよいよ**本物のファイル**に読み書きします。やることは4つ:

1. 読み書きの共通インターフェース `Storage` トレイトを決める
2. **ファイル版**（`file.rs`）: 末尾に追記する／先頭から順に読む（スキャン）／クラッシュで壊れた末尾を直す
3. **ファイルロック**（`lock.rs`）: 他のプロセスと同時アクセスがぶつからないようにする
4. **メモリ版**（`memory.rs`）: `:memory:` 用。ファイルを使わずメモリだけで同じことをする

## なぜ必要か

- `Storage` トレイトという「共通の窓口」を1枚かませると、上のレイヤー（`Db`
  ）は「ファイルなのかメモリなのか」を気にせず同じコードで動かせます。テストはメモリ版で速く回し、本番はファイル版、という使い分けができます。
- クラッシュ回復（torn write）をここで吸収しておくと、上のレイヤーは「開いた時点で必ず正しい状態」を前提にできて、考えることが減ります。

## 出てくる言葉

| 言葉             | 意味                                                        |
|----------------|-----------------------------------------------------------|
| append-only ログ | 末尾に足すだけのファイル。途中を書き換えない。                                   |
| スキャン (scan)    | ファイルを先頭から順に1フレームずつ読んでいくこと。                                |
| 書き込みカーソル       | 「次に追記を始める位置（＝今のファイル末尾）」を覚えておく値。                           |
| torn write 回復  | クラッシュで末尾が中途半端になったファイルを、最後の正常なフレームまで切り詰めて直すこと。             |
| truncate       | ファイルを指定の長さに**切り詰める**操作。                                   |
| fsync          | OSのキャッシュを実ディスクに確実に書き出す。`File::sync_data()`。               |
| アドバイザリロック      | 協調的なファイルロック。`fs4` の `lock_exclusive()` / `lock_shared()`。 |
| 排他ロック / 共有ロック  | 排他=1人だけ（書き込み用）/ 共有=複数OKだが排他とは両立しない（読み取り用）。                |

## 手順（タスク）

### 1. `Storage` トレイト（`mod.rs`）：読み書きの共通窓口

「ファイル版もメモリ版も、最低限これだけはできる」という関数の集まりを決めます。

- [ ] トレイト `Storage` を定義
    - [ ] `append(&mut self, bytes: &[u8]) -> Result<u64>` … 末尾に書いて、**書き始めたオフセット**を返す（後でその位置を
      index に覚えさせる）
    - [ ] `read_at(&self, offset: u64, len: usize) -> Result<Vec<u8>>` … 指定位置から len バイト読む（ペイロード遅延ロード用。§9.2）
    - [ ] `len(&self) -> u64` … 現在のファイルサイズ
    - [ ] `sync(&mut self) -> Result<()>` … fsync（メモリ版は何もしない no-op）
    - [ ] `truncate(&mut self, len: u64) -> Result<()>` … 指定長に切り詰め（torn write 回復用）
    - [ ] ヘッダ（先頭64B）の read / write
    - [ ] compact 用フック: 「隣に一時ストレージを作る」「それで元を置き換える（rename）」
- [ ] `:memory:` の判定（パス文字列が `":memory:"` と等しいか）は、ここか `db.rs` のどちらかで吸収する

### 2. ファイルバックエンド（`file.rs`）

- [ ] **open（既存を開く）**: ファイルを RW か RO で開き、先頭64バイトを読んで `Header::decode`（M1）で検証
- [ ] **create（新規作成）**: 新しいファイルにヘッダを書く。既に存在したら `AlreadyExists`
- [ ] **追記 (append)**: 末尾にシークして write。次に書く位置（書き込みカーソル）を覚えておく
- [ ] **スキャン `scan_frames()`**: 先頭→末尾の順に `(offset, DecodedFrame)` を1件ずつ列挙する
    - [ ] バッファ読み（`BufReader` か自前バッファ）で「`record_len` を読む → その分だけ body+crc を読む」を繰り返す
    - [ ] **torn write 回復（§5.3）— ここが山場**:

      | 状況 | 判定 | 対応 |
          |---|---|---|
      | 末尾のバイトが足りない／**最後のフレームだけ** crc NG | 書き込み途中でクラッシュした（torn write） | RW: そのフレーム手前まで `truncate` してカーソルを合わせる。RO: 末尾以降を無視（ファイルは変更しない） |
      | **途中（末尾でない）**のフレームが crc NG | 回復不能な破損 | `Corrupt` エラー |

      > 考え方: 追記オンリーなので、壊れるとしたら「今書いていた一番最後」だけのはず。だから末尾の破損は“クラッシュ”として救済、途中の破損は“異常”として諦める。
- [ ] `sync`: `File::sync_data()`（または `sync_all`）。`SyncMode` をいつ適用するかは `db.rs` 側の判断だが、強制 sync
  の口だけここで用意
- [ ] 親ディレクトリの fsync ヘルパ（rename を確実に永続化するため。compact で使う）
- [ ] 残っている `<db>.compact` 一時ファイルの検出・削除フック（M6 から呼ぶ。§5.3 / §7）

### 3. ファイルロック（`lock.rs`）

- [ ] `fs4`（または `fs2`）で実装
    - [ ] RW で開く → **排他ロック** / RO で開く → **共有ロック**（§8.1）
    - [ ] `lock_wait=false` … 取れなければ待たずに `Locked` エラー / `lock_wait=true` … 取れるまで待つ
    - [ ] ロックの「持ち手（ガード）」を `Db` が保持し、`Db` が捨てられる（`Drop`）時に自動で解放する
- [ ] ロック対象は DB ファイル自体に flock する案が基本。別のロックファイルを使う方式にするかは、メモに残して後で判断

### 4. メモリバックエンド（`memory.rs`）

- [ ] 中身を `Vec<u8>` で持つ `Storage` 実装（append / read_at / len / truncate はベクタ操作で実現）
- [ ] `sync` / ディレクトリ fsync / ロックは**何もしない（no-op）**
- [ ] compact は「新しい `Vec<u8>` に詰め直す」で表現（§10）

## 動作確認（受け入れ条件）

- [ ] create → 複数回 append → 閉じて再 open → `scan_frames` で**同じ並びが復元**される。
- [ ] 末尾を途中でぶった切ったファイルを RW で open すると、`truncate` されて有効フレームだけ残る。途中破損は `Corrupt`。
- [ ] 2つ目の RW open が `Locked`（`lock_wait=false`）。RW を持っている間の RO open も `Locked`。RO 同士は同時OK。
- [ ] `memory.rs` が `file.rs` と**同じトレイト経由で**同じテストを全部通る。

## つまずきポイント / 実装メモ

- `Storage` は同期 I/O（async は v1 では作らない）。
- mmap は使わない（ベクトルはアリーナにメモリ常駐させる方針。§9）。将来 read を mmap 化したくなっても `read_at`
  の中身を差し替えれば吸収できる。
- flock は**アドバイザリ（協調的）**＝守る気のないプロセスは無視できる。「非協調プロセスからは守れない」とドキュメントに明記する。
- torn write 回復のテストは「正常なファイルを作る → 末尾を数バイト削る → open し直す」で簡単に再現できる。M8 でも使う。
